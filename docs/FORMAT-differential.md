# FORMAT-differential — the differential artifact, frozen

**Status: FROZEN as of B4.0.** This document is the specification. **Both decoders are checked against
it, and neither is checked against the other.**

**Why this is its own document and not a section of `DESIGN-B4`:** a frozen surface with a corpus
promise is read by people who are not reading the phase's design record, and **a format buried in a
phase doc acquires the phase's lifetime rather than the format's.** `table_format.h` is the precedent.

---

## 0. What this format is for, and what promise it carries

A **differential artifact** is one run of the B4 rig: the operations issued, the watermark the C++
engine reported, the state it recovered, the provenance of both engines, and **the verdict the judge
reached.**

**B4-Q3, ruled:** it is frozen, with the corpus promise attached — and the promise is the strict form:

> **A STORED ARTIFACT MUST REPRODUCE ITS FINDING, NOT MERELY REPLAY.**
>
> It is not enough that the artifact runs again. **It must produce the same verdict**, which is why
> the verdict it produced is *in* the artifact, and why a replay reaching a different one **fails**
> rather than quietly reporting the new answer.

**A defect found through a scratch artifact is a defect you cannot hand anyone.** That is what the
extra cost buys, and it is much cheaper to build in than to retrofit.

---

## 1. TWO INDEPENDENT DECODERS, AND THE ONE CONDITION ON THEM

The C++ side writes and classifies; the Go judge reads. **They are two implementations of this
document, deliberately.**

> **A SHARED DECODER MAKES WRITER AND READER AGREE BY CONSTRUCTION, AND THE SINGLE BUG A FROZEN FORMAT
> EXISTS TO CATCH IS A DISAGREEMENT ABOUT WHAT THE BYTES MEAN. BYTE-FOR-BYTE AGREEMENT IS THE THING
> UNDER TEST, SO IT CANNOT BE THE THING ASSUMED.**

This is `ModelRange::Covers`' reasoning one level up: there, the harness keeps its own half-open test
so that a boundary bug cannot be invisible from both sides at once. Here, the two sides are in
different languages and the shared blind spot would be a whole format.

**THE COST, STATED HONESTLY: a second implementation, maintained.** Two decoders can drift, and
nothing about writing this sentence prevents it.

**WHAT MAKES IT AFFORDABLE: the fixtures are the shared artifact rather than the code.** Both decoders
are checked against **the same committed bytes**, so the thing kept in step is a set of files, not two
code paths.

**THE CONDITION ON THE PAIR, and it is what makes the independence real rather than nominal:**

1. **NEITHER DECODER'S FIXTURES MAY BE GENERATED BY EITHER ENCODER.** The fixtures in
   `seeds/differential/format/` are **hand-built from this document**, field by field. A fixture built
   by the production encoder tests that the decoder agrees with the encoder — which is the question
   this pair exists to *not* assume.
2. **A MUTANT MAKES THE TWO DISAGREE** — a field the C++ writer emits in one order and the Go reader
   expects in another — **so the pair's value is demonstrated rather than argued.** If nothing catches
   that, the second implementation is not buying what it costs.

## 2. The bytes

```
artifact = header || section* || footer

header:
  magic:[8]u8        = "RIFTDIF\0"
  format_version:u32 = 1
  section_count:u32

section:
  kind:u8
  length:u32
  payload:[length]u8

footer:
  magic:[8]u8        = "RIFTDIF\0"      -- again, so a truncation is not a short read
  crc32c:u32                            -- over every byte before it
```

**THE MAGIC APPEARS TWICE, AND THE SECOND ONE IS NOT DECORATION.** A file truncated anywhere in the
middle still begins with a valid header. Without a trailing magic the reader would have to discover
the truncation by running off the end of a section, which reports *"malformed section"* for a file
that is not malformed — it is **incomplete**, and an operator needs those told apart.

**`crc32c` is the same implementation the WAL and the SSTable use.** One checksum in this engine.

### Section kinds

| kind | name | payload |
|---:|---|---|
| 1 | `PROVENANCE` | `engine_commit:str` `model_commit:str` `seed:u64` `flush_bytes:u64` `wal_buffer_bytes:u64` `max_record_bytes:u64` |
| 2 | `SUBMISSION` | `op_count:u32` then `op*` |
| 3 | `WATERMARK` | `w:u64` |
| 4 | `RECOVERED` | `entry_count:u32` then (`key:str` `value:str`)* |
| 5 | `VERDICT` | `outcome:u8` `why:str` |

`str` is `length:u32 || bytes`. Every integer is little-endian.

```
op:
  kind:u8        1 = SET, 2 = DELETE, 3 = DELETE_RANGE, 4 = SYNC,
                 5 = SNAPSHOT_TAKE, 6 = SNAPSHOT_RELEASE
  seq:u64        the sequence the rig assigned, or 0 for ops that consume none
  key:str        SET/DELETE: the key. DELETE_RANGE: the start, empty if unbounded
  value:str      SET: the value. DELETE_RANGE: the end, empty if unbounded
  flags:u8       bit 0: DELETE_RANGE start is bounded
                 bit 1: DELETE_RANGE end is bounded
```

**`flags` EXISTS BECAUSE AN EMPTY KEY IS A VALID KEY.** `db.h`'s divergence 3 says it in the engine;
the same distinction has to survive into the artifact, or `DeleteRange(At(""), At(""))` and
`DeleteRange(Unbounded, Unbounded)` become the same bytes — and those are §8.2's clear-everything case
and a range that deletes nothing.

## 3. WHAT THE CLASSIFIER REFUSES — the specification, not a description

**Written before either decoder existed**, so neither can have been written to agree with an
implementation. Each row is a shape a hand-built fixture produces.

| refused | why it is a rule and not a preference |
|---|---|
| header magic is not `RIFTDIF\0` | a foreign file is a different report from a damaged one, and an operator needs to be told which |
| **trailing** magic is not `RIFTDIF\0` | **the file is incomplete, not malformed.** Without this the truncation is discovered as a section overrun and misreported |
| `crc32c` mismatch | the only whole-file integrity check there is |
| `format_version` is not 1 | **refused, never guessed at.** A future version means fields this build cannot place |
| a section's `length` runs past the footer | every offset is bounds-checked before it is followed, as in `table_check.cc` |
| **an unknown section kind** | **REFUSED, NOT SKIPPED.** A corpus artifact whose unknown section is silently ignored has lost the thing it was meant to carry, and reports success |
| a duplicate section kind | two answers to one question, with nothing to decide between them |
| any of the five sections missing | all five are required. An artifact without its verdict cannot reproduce a finding; without its provenance it cannot name what it ran against |
| sections not in **ascending kind order** | **canonical ordering, so two artifacts of one run are byte-identical.** Without it, "the same run produces the same bytes" is false and the corpus cannot be diffed |
| trailing bytes after the footer | the footer ends the file; anything after it is a second file or a mistake, and neither is this one |
| `SUBMISSION` with `op_count == 0` | an artifact of nothing reproduces nothing |
| `RECOVERED` keys not **strictly ascending** | the comparison is a set comparison; duplicates would let one decoder see a key the other does not, and unsorted keys make byte-identity depend on insertion order |
| `VERDICT.outcome` names no enumerator | the range check comes first, because the byte came off disk. `-Werror=switch` is about enumerators that exist |
| `PROVENANCE.engine_commit` or `model_commit` **empty** | **B4-Q1.** *An artifact naming no commit is the same defect as an exit run at an uncommitted tree naming a commit that does not contain what ran* |
| either commit ending in `-dirty` | a run at an uncommitted tree cannot be reproduced, so an artifact claiming to be one is refused at the door |

**AND ONE REFUSAL THAT IS NOT ABOUT THE BYTES.** A `SUBMISSION` whose op sequences are not
non-decreasing is refused: the rig assigns them and the model replays in that order, so a log the
model cannot replay in order is a log the judge cannot use — and finding that out in the judge would
report it as a divergence in the engine.

---

## 4. What is NOT in this format, and why

- **No timestamps.** They would make two artifacts of one run differ, which destroys the byte-identity
  the ascending-order rule buys.
- **No hostname, no username, no path.** Provenance is what is needed to *reproduce*: two commits, a
  seed, and the caps. Anything else is metadata that ages.
- **No compression.** A corpus artifact that needs a decompressor to be read has a second format
  inside it, and this one is frozen.
- **No engine-side interpretation.** The `RECOVERED` section is what the engine held, as key-value
  bytes. The artifact never records what the engine *believes* about its state — `B3-D2b`'s rule,
  which is the whole reason a differential is worth running.
