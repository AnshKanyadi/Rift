# Rift v1 — what exists, what was verified, how, and what the verification cannot see

*Written for somebody who has never opened this repository and is not going to read the design
documents. Every number here comes from an exit run, a lane, or a measurement recorded at the time it
was taken. Where a number is a criterion rather than a measurement, it says so. Where something was
not measured, it says that too — in this document, not in an appendix.*

---

## 1. What this is

A distributed, transactional, MVCC key-value database, built from scratch:

- **The distributed layer is Go.** Multi-group Raft — elections, log replication, persistence,
  snapshots, pre-vote, leadership transfer, single-node membership changes with learner catch-up.
  Data is split into ranges, each its own Raft group, splitting under load. MVCC over hybrid logical
  clocks. Percolator-style snapshot-isolated distributed transactions. Linearizable reads via read
  index.
- **The storage engine is C++.** A from-scratch LSM: skiplist memtable, checksummed WAL, block-based
  SSTables with bloom filters and a block index, leveled compaction, a MANIFEST/version-set, and range
  tombstones — reached from Go through a batch-oriented cgo interface.
- **It runs for real.** Three operating-system processes over TCP sockets, killed with `SIGKILL`,
  restarting against whatever the kill left on disk.

**The point of the project is the second half of the title.** Implementing Raft is not the hard part.
Knowing whether your implementation is wrong is.

## 2. The phases, and what each had to prove

Every phase is gated: nothing starts until the previous one's exit criteria are signed off, and the
criteria are written **before** the code. "Green" means the exit run completed with **zero safety
violations** under that phase's fault mix.

### Track A — the Go distributed layer

| phase | what it added | exit gate | state |
|---|---|---|---|
| **A0** | simulator, fault injectors, the `Clock`/`Rand`/`Transport`/`Engine` interfaces, the seed CLI | a toy survives 1,000 seeds; identical seeds give identical traces; injector fire counts asserted; the mutant suite kills every mutant | **signed** |
| **A1** | single-group Raft: elections, replication, persistence with correct sync ordering, the figure-8 commit rule | 10,000 mixed-fault seeds, porcupine green, **and a non-empty BUGS.md** | **signed** |
| **A2** | snapshots, log compaction, pre-vote, leadership transfer | crash storms plus partitions with snapshot transfers in flight, 10,000 seeds | **signed** |
| **A3** | single-node membership changes, learner catch-up, config-across-snapshot | continuous membership churn under faults, 15,000 seeds | **signed** |
| **A4** | multi-raft: range descriptors with epochs, size-threshold splits, router retry, manual rebalance | workloads spanning many splits mid-traffic, per-key linearizability, 10,000 seeds | **signed** |
| **A5** | MVCC, versioned key encoding, version GC, HLC with `maxOffset` | MVCC semantics suite deterministic and green; HLC causality under skew | **signed** |
| **A6** | Percolator transactions, uncertainty intervals, reader-side lock resolution | 25,000 seeds: conservation, atomicity, SI green | **signed** — commit `c807555`: pass 24,903, violations **0**, inconclusive 97 |
| **A7** | read index, follower reads, the term-start no-op | staleness green under partitions and leader churn, 25,000 seeds | **signed** — commit `b730acf`: pass 24,900, violations **0**, inconclusive 100, errors 0 |

**A7's exit run in full**, because it is the most completely recorded: eight contiguous shards tiling
`[0, 25000)` with no gap and no overlap, all at one commit, aggregated by a test that *checks* the
tiling rather than trusting it. 5h54m–6h02m per shard. **Inconclusive rate 4.0 per mille** against a
threshold of 30 — and **an inconclusive is never counted as a pass.**

## 3. What was found: 67 defects

`BUGS.md` carries, for each: the symptom, the seed or kill point, the root cause, the fix, **the
invariant that caught it**, which mutant class would have caught it, and what it would have caused in
production. If no existing mutant class would have caught it, a new one lands in the same change as
the fix.

**60 in Track A and integration, 7 in Track B.** What found them is the distribution worth reading:

| found by | count |
|---|---|
| the harness checking itself, or somebody reading its own record | 14 |
| structural assertions inside `raft/` and the driver | 6 |
| **persist-before-reply** — a message may not attest to state that is not on disk | 4 |
| **snapshot equivalence** — a node's state must equal the log's state at its position | 4 |
| **conservation, atomicity, snapshot isolation** | 5 |
| **per-key linearizability** (porcupine) | 3 |
| a **non-vacuity counter reading zero** | 2 |
| the rebalance oracle, a plain sweep, inspection, an enumeration, a false accusation chased down | 5 |
| the kill-point sweep and differential tests (Track B) | 7 |
| **I2's real-mode gates and counters** | 12 |

**Four a stranger should read:**

**BUG-060 — the cluster could not re-elect a leader.** After any leader kill, all three nodes sat at
`follower`, `term=2`, forever. Ticks advanced, bytes flowed, requests were admitted, **and nothing was
ever served again.** `preCampaign` reset the election timer without clearing `r.leader`, so the
pre-vote refusal *"I heard from a leader inside one election timeout"* read as true when what had
happened was *"I campaigned recently"* — and `r.leader` still named the node that had just died. Three
followers each doing that refused each other indefinitely. **The fix is one line.**

> **Fourteen seconds serving nothing, with every oracle green and correct to be green.** A Raft
> liveness bug that survived eight phases and 25,000 seeds, found by a **threshold declared in advance**
> rather than by any checker. That is this project's strongest single argument for declaring what a
> result must show before taking it — and it is evidence rather than principle.

**BUG-046 — a byte-identical trace hash from an engine that was never opened.** The run reported the
same hash it always had; the engine directory was empty. Every other signal said success.

**BUG-055 — the benchmark measured the checker.** Throughput on a fault-free cluster fell monotonically,
1938 → 478 ops/s over thirty seconds. `store.Config` required the simulator's oracle ledger, which
retains every message and every applied entry — **875 bytes per operation, measured.** Correct for a
bounded run; real mode is the first thing here that does not end.

**BUG-057 — "it does not link on this machine" was an unread error.** It links. The archives were in
the tree, built, 7.7 MB. That paraphrase narrowed the phase's claims *and then narrowed a ruling made
on it*, which is why the rule it produced is mechanical: **no claim is narrowed, deferred or scoped on
a paraphrased error; the verbatim output goes in the report beside the reduction.**

## 4. The register: 30 instances of verification that verified nothing

The most productive artifact in this repository is a numbered list of times a checking mechanism
reported success while checking nothing. Most of the standing rules came out of it.

**#8 — the oracle asked the accused.** The checker whose job is catching a node that claims durability
it does not have was comparing that node's claims against *the engine's view of what it held*. The
design document had already written *"an oracle which interrogates the engine believes the lie"*, and
the implementation did it anyway, in the mechanism that sentence was written to protect.

**#23 — an opt-out is a claim that switches off its own instrument.** A mutant class carried a written
exemption saying the sweep could not reach it. The lane skips any class with an exemption, so the claim
was never measured. When it finally was: **280 detections in 300 seeds.** False the day it was written.

**#26 — two tests written for this exact failure mode, both vacuous.** Written by someone who had spent
that day documenting twenty-five prior instances, to assert two properties that had just been ruled on.
Both passed under the exact mutation each existed to catch. **One command found both.**

**#27 — a checker wired into something that never calls it.** A7's differential oracle was appended to
a list of step-oracles driven by a method it does not implement. It compared **zero** answers on every
seed of every run.

> The register's thesis is that this is not a competence problem. **#26 is the experiment**: maximum
> attention, maximum recent exposure, an explicit rule requiring exactly this check — and the tests
> were still vacuous, and no amount of reading them would have shown it.

## 5. The standing rules, and the defect behind each

| rule | the defect behind it |
|---|---|
| **No gate counts until its failure has been induced.** | Checkers that had never been watched go red, several of which could not. |
| **An oracle must fire on its plant *and* be silent on a clean tree**, at a stated seed count. | A7's differential oracle passed the first test while wrong in a way that would have failed clean runs. |
| **Every mutant carries a detection floor AND a seeds-to-detection ceiling.** | A class kept its rate while its first detection moved from seed 145 to 553. |
| **An exclusion may cite a measurement or an argument about reachability — never the excluded class's own declaration.** | Register #23. |
| **Started is read from the process, never from the launch.** | An exit run believed to be running for two hours had refused at launch. |
| **The tree state is read from the tree, never from the revert that was supposed to have happened.** | A killed measurement left a mutant applied; three later floors read plausible. |
| **Liveness is read from the CPU clock, never the wall clock.** | A two-hour timeout that had not fired at 2h56m, because the machine had slept. |
| **An inconclusive is never a pass.** | A linearizability checker that could not conclude was being banked as green. |
| **A directed test that arranges a precondition must assert that it arranged it.** | Four of this project's own directed tests silently arranged nothing. |
| **No claim is narrowed on a paraphrased error; the verbatim output goes beside the reduction.** | BUG-057, which narrowed a phase's claims and a ruling on a premise nobody had read. |
| **Correcting a precondition is not the same act as loosening an assertion, and the record says which.** | A durability cross-check whose precondition was engine-specific; the diff for the two looks identical. |
| **Inducing a gate by editing the runner proves the code path; only a real misbehaving cluster proves the mechanism.** | `chaos/`'s gates, every one of which had been induced by hand and none against a cluster actually doing the thing. |

**The three-rule chain is one rule seen three times** — *read the thing, not the proxy for the thing* —
and the part that makes it actionable is that **the discriminator was available every time**. `ps`
before the first, `git diff` before the second, `ps -o time=` before the third.

> **The failure is not missing instrumentation. It is reading the number that was easier to reach.**

## 6. How it is verified

| instrument | what it does |
|---|---|
| **deterministic simulation** | one event loop, virtual time, a seeded PCG64. Same seed, same trace, byte for byte, on the Go reference engine |
| **the oracles** | election safety, log matching, leader completeness, state machine safety, persist-before-reply, snapshot equivalence, conservation, atomicity, snapshot isolation, rebalance safety, read-index agreement |
| **porcupine** | per-key linearizability over the client's own history |
| **78 Go mutant classes** | each with a covering test and a measured detection floor or a named instrument |
| **155 C++ mutant classes** | the same discipline on the engine |
| **22 blind patches** | the determinism analyser mutation-tested against itself |
| **the kill-point sweep** | the C++ engine killed at every `Env` call in flush, compaction and manifest swap, then reopened and checked against the operation log |
| **differential testing** | identical operation sequences to `engine/model` and the C++ engine; full iterator output byte-identical |
| **`determinismcheck`** | a `go/analysis` pass banning `time.Now`, global rand, map range, floats and concurrency in core scope. **5 escape hatches, each a single line with a written reason** |
| **26 corpus bundles** | every historical defect replays from a plan bundle at any commit |
| **real mode** | three processes, real sockets, `SIGKILL`, real recovery on the C++ engine |
| **the calibration fixture** | `riftnode --fault=...` breaks its own guarantees on purpose, so every real-mode mechanism has a positive control |

## 8. What this verification cannot see

*This section is in the same document as the claims, on purpose. A document that states what it cannot
claim is the one worth trusting on what it does.*

### 8.1 A signed phase is signed against a fault mix, not against the world

**Two measured demonstrations:**

- A mutant planting a real defect was detected **once in 3,000 seeds** under one phase's fault mix and
  **zero times** under the previous phase's. The defect did not change; the schedule did.
- **A phase whose headline feature is hybrid logical clocks ran its entire verification with clock skew
  injection switched off.** The configuration said `Holds = 0` — correct when written two phases
  earlier, false from the moment clocks mattered. Turning it on immediately produced a defect.

> "Zero violations" always means **zero violations under the schedules that were generated**, and the
> schedules are a choice.

### 8.2 Idealizations built into the simulator

- The network is **fair-lossy with bounded delay**: dropped, delayed, duplicated, reordered — not
  corrupted, not delivered arbitrarily late.
- The disk fails in **modelled** ways. Unsynced writes are lost on crash; bit rot and torn sectors are
  the C++ engine's territory.
- **Clock skew is bounded by `maxOffset`** in safety runs. Runs exceeding it are a separate experiment.
- **One process per node.** Resource contention between co-hosted ranges is not modelled.
- **Determinism is guaranteed on the Go reference engine only.** The C++ engine's correctness rests on
  the `Env` fault rig, kill-point sweeps, differential tests and corpus reruns.

### 8.3 "Byte-identical" needs a noun

`sim.Trace` folds `(step, instant, kind, node, payload **length**)` — **not payload content.** Every
"byte-identical trace hash" claim in this repository rests on that.

| instrument | catches | misses |
|---|---|---|
| trace hash | event **shape** | anything inside a payload that keeps its length |
| history comparison | **client-visible values** | anything that never reaches a client |
| the two together | both | internal state reaching neither |

### 8.4 A6's headline rests on machinery three mechanisms were meant to exercise, and none did

Snapshot isolation over hybrid logical clocks is a v1 headline, and A6 is signed. **This is a coverage
statement, not a correctness one:**

| | |
|---|---|
| **established** | `hlc`'s implementation has been analysed by the determinism pass since BUG-048; A6's oracles are correct and were induced individually; the uncertainty-restart machinery exists and runs |
| **NOT established** | that it behaves correctly **under actual clock disagreement**, by any of the three mechanisms meant to check it |

A6's sweep ran with skew off; `hlc` was never analysed until BUG-048; real mode cannot produce skew at
all. Each was defensible alone. **A claim covered by three mechanisms is not three times as safe if
nothing checks that any of them fired.**

### 8.5 Nothing in this project gates liveness

The safety oracles cover anything that makes a **wrong** thing happen. **Nothing covers anything that
makes the right thing stop happening.** BUG-060 is the demonstration: a cluster serving zero operations
for fourteen seconds, every oracle green and correct to be green, because a cluster that elects nobody
does no wrong thing — and porcupine is green over a history of timeouts, since a timeout is
*may-or-may-not-have-happened*.

The shape of the answer is a liveness floor derived from `Election` and `Heartbeat` the way I2's
`R ≤ 2.5E` was, then measured against real schedules before it could gate. `LedTicks == 0` is the only
liveness assertion in the tree, it is binary, and it would not have caught BUG-060 either.

### 8.6 A chaos green is weaker than any simulated green

**There is no seed.** The schedule was the operating system's and the timing was the network's, and
neither is recoverable — so a second run is a **different experiment**, not a repetition. It can
neither confirm a result nor refute it. Every chaos green prints that sentence in the same bytes as the
result.

### 8.7 The real-mode path has one phase of coverage, not eight

`chaos/`, `bench/`, `net/` and `cmd/riftnode` had **zero mutants and appeared in no CI lane** until I2
closed. Seven `chaos/` tests guarded on `testing.Short()` and therefore never ran in the push lane at
all. That is now fixed — `make chaos-smoke`, a calibration fixture, seven mutants all killed — but it
is **one phase of coverage against Track A's eight.**

### 8.8 Named obligations, with the configuration each requires

| obligation | needs |
|---|---|
| **T4 — cgo boundary cost under chaos** | a native C++ harness result for the same workload at the same block size. **Unmeasured, not passed** |
| **Clock skew in real mode** | a real-mode clock with injectable per-node offset and jump schedule, plus the uncertainty oracle on a real-mode ledger |
| **A liveness floor** | derived from `Election` and `Heartbeat`, then measured against real schedules before it gates |

## 9. Open items, carried rather than closed

**A v1 that names its open items is finished. One that quietly closes them is not.**

| item | state |
|---|---|
| **T1's 500 ms excess** | worst `R = 1.75s` against a 1.25s threshold, nothing failing to recover. **Measured and unexplained.** Threshold not adjusted, excess not chased |
| **OPEN-I2-1** | one `signal: killed` uninvited exit whose cause was never established. The `exit status 1` occurrences are explained (BUG-054); this one is a different symptom and the same cause is not assumed. Both sides now print pids, so the next occurrence is decisive |
| **the rebalance driver reads `ledger.Ranges()`** | `sim/hunt`'s workload consults the oracle's data structure, so the observer is coupled to the **workload**, not to the system. The ledger-identity test is scoped around it |
| **`./sim/hunt/` lane cost** | exceeds a 3,000s test timeout at 40 seeds. A lane-cost problem, not a failure; the safety oracles run separately |
| **`BUG-015` STALE** | red on both `corpus` and `corpus-reproduces`. Its STALE status — the mutant changing nothing at all on that schedule — is established **on the pre-fix tree, where its recording was current**. At HEAD `1a35d04` moved its trace too, so `corpus-reproduces` now correctly reports `PRECOND` rather than re-asserting STALE it cannot currently evaluate. Its trace is deliberately NOT re-recorded: that would pin a schedule reproducing nothing. Both lanes stay red and say which question each is declining to answer. **The first push to `origin` was made over this red with `RIFT_SKIP_HOOK=1`, knowingly**: all nine pre-push lanes were run past the first failure and BUG-015 is the ONLY failure, reached twice (`test` and `corpus`). The hook is correct to refuse and nothing measured was changed to get past it |
| **`BUG-019` re-pinned after BUG-060** | BUG-060's one-line pre-vote fix left its seed-9 plan no longer reaching `M65` — checked with a current recording, so it is the bundle and not the lane. Re-pinned at seed **14** by search: 10 detections in 300 seeds against **0 of 300** on the unmutated tree |
| **`corpus-reproduces` could not tell a stale recording from a lost finding** | Its criterion is a DIFFERENCE from the recording, which a stale recording cannot support, and it reported the un-evaluable case as *"the bundle no longer carries its finding"*. Induced on one plan: stale recording **WEAK**, same plan and same code with a current recording **ok**. It cost `BUG-011` its place in the corpus for a session and produced a false written claim before a byte-identical `plan.json` gave it away. Fixed — the lane now reports `PRECOND`, both branches induced. **The rule it broke was already written down: a directed test that arranges a precondition must assert that it arranged it** |
| **the differential generator's zero-length-value hole** | Track B; a value length the generator never produces |
| **cross-toolchain determinism** | unmeasured — the trace-identity claim has only been checked on one toolchain |
| **`make mutant-covered`** | unrunnable on this machine |
| **`power-mutants`** | unrun |
| **sweep-based covering tests** | eight of the mutant lane's covering tests are seed sweeps inherited from A1–A6, which is what puts `make mutants` over a two-hour baseline. A named, dated obligation due at whichever phase next touches each class |
