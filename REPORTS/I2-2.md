## The blocking question, settled: I was wrong

`go build -tags rift_cgo ./cmd/riftnode` fails with undefined symbols. **That is not a
toolchain fact.** `engine/riftcgo` carries only `-lstdc++` in its `#cgo LDFLAGS` deliberately —
the archive's directory is a build artifact the *caller* chooses, which is what lets the package
typecheck with no C++ build present. `make cpp-cgo` supplies it. I supplied nothing.

```
CGO_LDFLAGS="-L$(pwd)/engine-cpp/build/test -lrift_capi -lrift_engine" \
  go build -tags rift_cgo ./cmd/riftnode
→ links, 6.5 MB, runs
```

The archives were in the tree — built, dated, 7.7 MB. **BUG-057**, sixth in the reading tally.

> It narrowed the phase's claims, and then it narrowed a ruling, which was made on my report of
> an error nobody had read.

**GF-61**, the rule this earns: *no claim is narrowed, deferred, or scoped on a paraphrased
error. The verbatim output goes in the report beside the reduction.* The cost is asymmetric —
a paraphrase leading to **more** work is self-correcting, because the work meets the error
again; a paraphrase leading to **less** work is not, because nobody returns to it.

Two corollaries, applied: **a scope line names its own cause** (`PERSISTENCE NOT EXERCISED` was
true for a reason that had already evaporated), and **a refusal quotes what it refused**.

## BUG-059 — ruled, split, and a second layer underneath

`restart()` conflated a **state transition** with a **procedure**. Split, with no `skipCrash`
flag:

| | before | after |
|---|---|---|
| transition | `restart()` — crash, advance epoch, *and also recover* | `restart()` → calls `Recover()` |
| procedure | unnamed, inside `restart` | **`Recover()`** — exported, one definition |
| fresh cluster | `New()` — accepted a populated engine | `New()` — **fails** on one |
| process start over durable state | *no door* | **`Open()`** — fails on an empty engine, then recovers |

**The bad state is unrepresentable rather than avoided.** Four inductions; the fourth needed a
real observable, because over a stray key `Open`-with-`Recover` and `Open`-without are identical
machines — GF-56 again, caught this time by inducing rather than by reading.

### The second layer, found by implementing the first

```
store: node 1 recovered a state its own durability record disagrees with:
hard state recorded {Term:0 Vote:0}, engine returned {Term:1 Vote:1}
```

`restartFrom`'s cross-check carried **the same unnamed precondition one level down**: the
simulator restarts in-process, so the record was written by the incarnation restarting. A fresh
process has no record, and `HardState{}` is indistinguishable from a node that crashed before
voting.

> An "unset" that looks like a legitimate value is the ambiguity this project refuses everywhere
> else. Same shape, same answer: a separate bit.

The check is **not** made optional. It runs whenever a record exists; when none does the
read-back is **adopted and counted**, so a skipped comparison is visible.

**GF-57's second signature:** *an unexported path with one caller encodes that caller's
preconditions invisibly. When a second caller arrives the precondition is promoted to an
explicit argument or the path splits — never satisfied by the new caller pretending to be the
old one.*

## GF-60's three scope-limited rows, in full

**1. Clock skew bounded by `maxOffset`** — *sim:* drift and jump schedules, bounded in safety
runs and deliberately exceeded in the envelope experiment; the uncertainty oracle reads the
result. *Real mode:* **none.** `clock.NewReal(250ms)` reads the machine clock; no drift, no
jump, no per-node offset, so the HLC's uncertainty interval is never wide enough to force a
restart. **Disposition: NAMED OBLIGATION alongside T4** — not a print, because a print nobody
owns is how a gap survives a project. HLC uncertainty is the substance of A6's correctness
argument and real mode has never exercised it. *Configuration required:* a real-mode clock with
injectable per-node offset and jump schedule, plus the uncertainty oracle reading a real-mode
ledger.

**2. A crash discards unsynced writes** — *sim:* `TestEnv` sync-loss windows; storage recovery
asserts the acknowledged-synced prefix. *Real mode:* **exercised and unchecked.** A `SIGKILL`
discards whatever was unflushed, which is the real behaviour, but nothing compares what came
back against what was acknowledged. **Disposition: scope limit, printed.** Closing it needs the
client's acknowledged-write set compared against post-restart reads — a real-mode storage oracle
that does not exist.

**3. The mailbox rule** — *sim:* unrepresentable, one goroutine. *Real mode:* enforced by
**package boundaries and the `-race` lane**, not by `determinismcheck`, which excludes `node/`
by design (A5). **Disposition: recorded, not closed.** The one row whose enforcing mechanism
differs from the one enforcing every other determinism rule, and `-race` finds a violation only
on a schedule that interleaves.

## GF-62 — the harness under its own regime

**The strong claim is false and GF-61 was just written about exactly this.** Measured:

| what the 71 mutants modify | count |
|---|---|
| `store/` 30, `raft/` 19, `kv/` 8, `hlc/` 1 | system under test |
| **`sim/` 5, `sim/toy/` 4, `sim/hunt/` 4, `sim/checker/` 4** | **17 mutate harness code** |

Plus 22 blind patches over `tools/determinismcheck`. What is genuinely uncovered:

> **`chaos/`, `bench/`, `net/`, `net/tcp/` and `cmd/riftnode` have zero mutants and appear in no
> lane in `make ci`.**

**And it is worse than "no mutants."** `make test` is `go test -short ./...`, and every real
`chaos/` test guards on `testing.Short()`. Measured: **7 skips.** The supervisor, the end-to-end
cluster, the composition test and the chaos run **have never executed in the push lane.** They
ran because I ran them by hand.

### What it would take, in dependency order

1. **Get it into a lane at all.** A `chaos-smoke` target: one cluster, one leader kill, gate and
   verdicts, ~15s. Without this a mutant has no covering test to be scored against. **Low cost,
   blocked on nothing.**
2. **A calibration protocol.** `sim/hunt`'s mutants work because `sim/toy` exists. `chaos/` has
   no equivalent — no fixture cluster that violates on cue, so a mutant in the runner has
   nothing to fail against. Needs a fixture node that can return a stale read, answer twice,
   exit uninvited, or report a leadership it does not hold. **Medium cost. This is the real
   work.**
3. **The mutants** — every one of this phase's eleven defects is a class the suite lacks. **A2
   already requires them**; the amendment has been quietly inapplicable to a third of the tree.
4. **The report generators first, actually.** `Run.Report`, `Run.Gate`, `Run.Exercised` are pure
   functions from a `Run` to text. No cluster, no fixture, unit speed — and **all three of
   GF-59's defects live there.** Lowest cost, highest yield.

> The regime's absence is not why the defects existed — most are wiring errors in code written
> this phase. It is why **finding them depended on my reading the output**, a detection mechanism
> with no floor, no kill-time, and no way to notice when it degrades.
>
> **Every other checker here has a measured sensitivity. The one reading the chaos reports does
> not.**

Recommendation, not a plan. Scoping is Ansh's.
